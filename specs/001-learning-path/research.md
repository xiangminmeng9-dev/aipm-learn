# 研究文档: AI 生成个人学习路径

**日期**: 2026-04-30 | **分支**: `001-learning-path`

## 研究项

### 1. 弱项数据来源

**Decision**: 从技能树的 skill_modules 表获取用户技能评估数据，结合面试练习的弱项分析，汇总后传给 AI

**Rationale**: 项目已有 skill_modules 表存储用户技能评估进度，面试模块也有弱项分析数据。将两者汇总可以提供更全面的弱项画像，让 AI 生成更精准的学习路径。

**Alternatives considered**:
- 仅用技能树数据：缺少面试实战维度的弱项
- 仅用面试弱项：缺少系统性技能评估
- 用户手动输入弱项：增加用户负担，体验差

### 2. 学习路径输出结构

**Decision**: 输出推荐学习模块列表，每个模块包含名称、优先级（高/中/低）、预估时长（小时）、学习理由

**Rationale**: 这四个字段覆盖了学习路径的核心信息——学什么（名称）、先学什么（优先级）、学多久（时长）、为什么学（理由），满足用户制定学习计划的需求。

**Alternatives considered**:
- 仅模块名称列表：信息不足，无法制定计划
- 增加学习资源链接：增加 AI 幻觉风险，链接可能失效
- 增加每日排课表：过于细粒度，不够灵活

### 3. AI Prompt 输出格式

**Decision**: 学习路径内容使用 JSON 格式输出（结构化数据，便于前端渲染）

**Rationale**: 学习路径是结构化数据（模块列表），与竞品分析的报告内容不同，JSON 格式更适合前端渲染为卡片列表。与现有 JD 分析的输出模式一致。

**Alternatives considered**:
- Markdown 格式：模块列表渲染不如 JSON 灵活
- 两次调用：不必要，一次调用即可

### 4. 数据持久化方案

**Decision**: 使用 Supabase PostgreSQL 新表 `learning_paths`，启用 RLS，与现有技能树数据表模式一致

**Rationale**: 与项目现有数据持久化方案一致，RLS 保证数据安全。

**Alternatives considered**:
- 复用现有表：字段差异大
- 纯本地存储：无法跨设备同步
