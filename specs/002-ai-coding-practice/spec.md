# 功能规范: AI Coding 练习工具

**功能分支**: `002-ai-coding-practice`
**创建时间**: 2026-04-14
**状态**: 草稿
**输入**: 用户描述: "开发一个 AI Coding 练习工具，核心功能：输入 AI Coding 题目，生成开发范式流程（思考链形式），支持多种开发模式选择"

## 用户场景与测试 *(必填)*

### 用户故事 1 - 输入题目并获取开发流程指导 (优先级: P1)

用户打开 AI Coding 练习工具页面，在输入框中粘贴或输入一道 AI Coding 面试题目（例如："用 Claude Code 开发一个实时协作白板应用"）。系统以思考链（Chain of Thought）的形式，逐步展示完整的开发范式流程，包括：应该先问面试官什么澄清问题、如何将需求拆解为功能模块、每一步应该在 Claude Code 中输入什么指令、开发过程中需要重点关注的事项。

**优先级原因**: 这是产品的核心价值——将 AI Coding 面试的隐性知识转化为可操作的显性流程，帮助用户建立结构化的开发思维。

**独立测试**: 可以通过输入一道题目，验证系统是否返回包含"澄清问题→需求拆解→开发步骤→注意事项"完整结构的思考链输出来独立测试。

**验收场景**:

1. **给定** 用户在输入框中输入了一道 AI Coding 题目, **当** 用户点击"生成流程"按钮时, **那么** 系统以思考链形式逐步展示开发范式流程，包含至少以下环节：澄清问题、需求拆解、开发步骤、重点关注事项
2. **给定** 用户输入了一道复杂的多功能题目, **当** 系统生成流程时, **那么** 需求拆解部分将题目分解为独立的功能模块，每个模块有明确的输入/输出描述
3. **给定** 用户输入了一道模糊的题目, **当** 系统生成流程时, **那么** 思考链的第一步会列出应该向面试官提出的澄清问题，帮助用户明确需求边界

---

### 用户故事 2 - 选择开发模式获取定制化流程 (优先级: P1)

用户在输入题目后，可以选择不同的开发模式来获取针对性的开发流程指导。系统预设六种开发模式：
- **手写 spec.md 模式**: 指导用户如何从零编写功能规范文档，再基于规范进行开发
- **Claude Code Plan 模式**: 指导用户如何使用 Claude Code 的 `/plan` 命令进行规划和开发
- **Speckit 模式**: 指导用户如何使用 Speckit 工作流（specify → plan → tasks → implement）
- **Using Superpowers 模式**: 指导用户如何利用 `using-superpowers` 技能进行头脑风暴和需求探索
- **TDD 驱动模式**: 指导用户采用测试驱动开发——先编写失败的测试用例，再让 AI 生成实现代码，通过红-绿-重构循环完成功能
- **Prompt Engineering 模式**: 指导用户通过纯提示词迭代与 AI 对话完成开发，无需特定工具框架，聚焦于如何写出高质量 prompt

选择不同模式后，生成的思考链流程会根据所选模式调整具体的操作步骤和工具使用建议。

**优先级原因**: 不同用户熟悉不同的开发工具和工作流，定制化的流程指导能最大化工具的实用性，适配更广泛的用户群体。

**独立测试**: 可以通过同一题目选择不同开发模式，验证输出的流程步骤是否因模式不同而有差异来独立测试。

**验收场景**:

1. **给定** 用户已输入题目, **当** 用户选择"Claude Code Plan 模式"时, **那么** 生成的流程中包含 `/plan` 命令的具体使用方法和步骤
2. **给定** 用户已输入题目, **当** 用户选择"Speckit 模式"时, **那么** 生成的流程中包含 specify→plan→tasks→implement 的完整工作流步骤
3. **给定** 用户已输入题目, **当** 用户选择"手写 spec.md 模式"时, **那么** 生成的流程中包含 spec.md 的结构模板和编写指导
4. **给定** 用户已输入题目, **当** 用户选择"TDD 驱动模式"时, **那么** 生成的流程中包含先写测试、再实现、再重构的具体步骤
5. **给定** 用户已输入题目, **当** 用户选择"Prompt Engineering 模式"时, **那么** 生成的流程中包含提示词编写技巧和迭代优化策略
6. **给定** 用户未选择任何模式, **当** 用户点击生成时, **那么** 系统提示用户先选择一种开发模式

---

### 用户故事 3 - 思考链逐步展示与交互 (优先级: P2)

用户在查看生成的开发流程时，思考链以逐步展开的方式呈现（类似 AI 推理过程的可视化），而非一次性全部显示。用户可以展开/折叠每个步骤，查看详细内容。每个步骤标注序号和标题，便于用户跟踪进度。

**优先级原因**: 逐步展示的交互方式更符合"练习"场景——用户可以先思考当前步骤，再展开查看建议，增强学习效果。

**独立测试**: 可以通过生成一个流程，验证输出是否以可展开/折叠的步骤形式呈现来独立测试。

**验收场景**:

1. **给定** 系统已生成开发流程, **当** 用户查看结果时, **那么** 流程以编号步骤的形式展示，每步包含标题摘要和可展开的详细内容
2. **给定** 思考链正在展示, **当** 用户点击某个步骤时, **那么** 该步骤展开显示详细内容，其他步骤保持折叠状态（手风琴模式）或保持当前状态

---

### 边界情况

- 当用户输入空白内容或极短的无意义文字时，系统应提示用户输入有效的题目描述
- 当用户输入超长题目（超过 5000 字符）时，系统应提示字符限制或自动截断并告知用户
- 当 AI 生成过程中网络中断时，系统应显示友好的错误提示并提供重试选项
- 当用户快速连续点击"生成"按钮时，系统应防止重复提交（按钮防抖/禁用）

## 需求 *(必填)*

### 功能需求

- **FR-001**: 系统必须提供一个文本输入区域，允许用户输入 AI Coding 面试题目，支持多行文本和粘贴操作
- **FR-002**: 系统必须提供六种预设开发模式供用户选择：手写 spec.md、Claude Code Plan、Speckit、Using Superpowers、TDD 驱动、Prompt Engineering
- **FR-003**: 系统必须以思考链（Chain of Thought）格式生成开发范式流程，包含以下环节：
  - 澄清问题（应该问面试官的问题）
  - 需求拆解（将题目分解为功能模块）
  - 开发步骤（具体的操作指令和顺序）
  - 重点关注事项（常见陷阱和最佳实践）
- **FR-004**: 系统必须根据用户选择的开发模式，调整生成流程中的工具使用建议和具体步骤
- **FR-005**: 思考链的每个步骤必须以可展开/折叠的形式呈现，支持用户逐步查看
- **FR-006**: 系统必须在用户输入无效内容（空白、超长）时提供明确的错误提示
- **FR-007**: 系统必须在生成过程中显示加载状态，并支持取消正在进行的生成操作
- **FR-008**: 系统必须支持中文界面，所有 UI 文字、提示信息、占位符使用中文

### 关键实体

- **题目 (Problem)**: 用户输入的 AI Coding 面试题目，包含题目文本内容和字符长度
- **开发模式 (DevMode)**: 用户可选择的开发工作流范式，包含模式名称、描述、模式标识。六种预设模式：spec-md、claude-plan、speckit、superpowers、tdd、prompt-engineering
- **开发流程 (DevFlow)**: 系统生成的思考链输出，包含多个有序步骤，每个步骤有序号、标题、详细内容、步骤类型（澄清/拆解/开发/关注）

## 假设

- 用户具备基本的编程知识和 AI 工具使用经验（目标用户为准备 AI Coding 面试的开发者）
- 系统通过后端 API 调用 AI 模型生成思考链内容，而非基于规则的模板匹配
- 单次生成的流程内容长度合理（约 2000-5000 字），无需分页
- 用户一次选择一种开发模式进行流程生成
- 无需用户注册/登录，工具为开放访问的单页应用
- 六种开发模式为固定预设，无需用户自定义添加

## 成功标准 *(必填)*

### 可衡量的结果

- **SC-001**: 用户从输入题目到看到完整开发流程的等待时间不超过 15 秒
- **SC-002**: 生成的开发流程覆盖"澄清问题→需求拆解→开发步骤→注意事项"四个环节的完整率达到 100%
- **SC-003**: 不同开发模式生成的流程在"开发步骤"环节存在明显差异，差异率不低于 60%
- **SC-004**: 用户首次使用时，能在 30 秒内理解如何输入题目并选择模式开始生成
- **SC-005**: 系统在生成失败时 100% 显示可理解的错误信息和重试选项
