# 研究: AI Coding 实操

**日期**: 2026-04-30 | **规范**: [spec.md](./spec.md)

## 决策 1: 题目生成方式

**决策**: 使用 AI 实时生成题目，而非预置题库

**理由**: 用户要求题目随机且符合大厂标准，预置题库会很快重复。AI 生成可以每次产出不同题目，同时通过 prompt 控制题目质量（大厂面试风格、覆盖不同方向）。

**考虑的替代方案**:
- 预置题库（50-100道）：简单但容易重复，维护成本高
- 混合方式（预置 + AI 补充）：复杂度增加，收益不大

## 决策 2: 数据模型设计

**决策**: 使用单表 `spec_practices` 存储，维度评分和优化建议以 JSONB 字段存储，而非拆分为多表

**理由**: 维度评分（4个维度）和优化建议（3-5条）是固定结构，数据量小，JSONB 查询灵活且避免多表 JOIN。与项目中 `coding_methodologies` 表的 JSONB 使用方式一致。

**考虑的替代方案**:
- 多表拆分（spec_practices + spec_dimension_scores + spec_suggestions）：过度设计，查询复杂
- 纯文本字段：查询不便，无法按维度统计

## 决策 3: 评分 Prompt 设计

**决策**: 评分 prompt 要求 AI 输出 JSON 格式（包含总分、维度评分数组、优化建议数组），而非 Markdown

**理由**: 评分数据需要结构化存储和展示（分数条、维度雷达图等），JSON 格式便于解析和持久化。与项目中 `coding_methodologies` 的 JSON 输出方式一致。题目生成用 Markdown（阅读体验好），评分用 JSON（数据结构化）。

**考虑的替代方案**:
- Markdown 格式评分：解析不稳定，展示受限
- 分两次调用（一次评分一次建议）：延迟加倍，体验差

## 决策 4: 历史记录页面方案

**决策**: 新增独立页面 `/coding/spec-history`，而非在实操页面内嵌历史列表

**理由**: 与现有 coding 模块的"历史记录"页面（`/coding/flows`）模式一致。实操页面专注于当前练习，历史页面专注于回顾。

**考虑的替代方案**:
- 在实操页面底部嵌入历史列表：页面过长，交互混乱
- 用弹窗/抽屉展示历史：空间受限，无法详细查看

## 决策 5: 数据看板集成方式

**决策**: 在现有 `/api/learning/dashboard` API 中新增实操统计字段，前端在 settings dashboard 的 coding 区域新增实操卡片

**理由**: 与现有 dashboard 方案完全一致——后端聚合查询，前端 ECharts 展示。无需新建 API 或页面。

**考虑的替代方案**:
- 新建独立实操统计页面：过度设计，用户需要跳转查看
- 新建独立 API：与现有 dashboard API 重复
